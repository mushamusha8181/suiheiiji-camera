# 水平維持カメラ v1.7.0

Android向けの動画専用カメラです。スマホを傾けても映像の水平を保つことを最優先にし、端末差で「設定はあるのに実際には効かない」機能を減らした構成です。

## v1.7.0 削りすぎ監査

v1.6.0の最適化を逆方向から再監査し、必要な処理まで削っていないかを確認しました。中心機能の欠落はありませんでしたが、最適化の副作用になり得る箇所を補強しています。

- 古いCamera2 Handlerタスクがpause/resume後の新Sessionへ干渉しないよう世代/Handler確認を追加。
- staleなRepeatingRequest更新を捨てた場合もpendingフラグを必ず解除。
- AE/WB/端末手ブレ補正の状態確認を「最大90フレーム、確認できたら即終了」へ。
- AF LOCKタイムアウト/例外時に内部ON状態を残さず通常AFへ復帰。
- MediaCodecは対応結果だけキャッシュし、一時的な情報取得失敗を永久な非対応扱いにしない。
- CaptureSession再構成中は録画開始不可。
- 縦横切替の能力通知とMain/GPU側の向きが一時不一致になる経路を修正。
- 録画開始時水平基準は、最初の実センサー値を受信してから確定。
- 音声停止が完了しない場合は未完成動画を正常保存扱いにしない。
- onPause時のGL停止待ちを録画EOS終了より余裕のある値へ調整。

詳細は `CODE_HEALTH_AUDIT.md` を参照してください。

## v1.6.0 コード再監査

v1.5.0をもう一度全体監査し、機能追加ではなく「無駄な常時処理・重複処理・端末差バグ・停止競合」を中心に整理しました。

- 水平センサーは `水平補正OFF + 水準器OFF` なら登録しません。開始/停止も二重登録しないよう冪等化。
- 端末温度リスナーは録画中だけ登録し、停止・失敗・バックグラウンド移行で解除。
- 30fps録画では実測FPS監視を行わず、60fps時だけ計測。
- Camera2のCaptureResult監視は設定変更直後の短時間だけ行い、状態確認後はRepeatingRequestをコールバックなしへ切替。
- AF LOCKは端末が終端状態を返さない場合にタイムアウトし、永久監視しません。
- 45°モードのクロップ上限角は設定/解像度変更時だけ計算し、センサーイベントごとの18回二分探索を削除。
- Camera2設定更新はキュー内で合流し、Surface構成が変わらない設定ではCaptureSessionを作り直しません。
- カメラ切替時にAF/AE/WB/マニュアル露出の対応能力を再検証し、ISO/露光時間も新しいカメラ範囲へ再クランプ。
- MediaCodec能力一覧をキャッシュし、解像度/FPS候補ごとの全コーデック再走査を削除。
- 対応範囲へクランプ済みの映像ビットレートをVideoEncoder側で再度2Mbps以上へ上書きしていた二重補正を削除。
- 外部 `.cube` LUTはバックグラウンド解析。パーサーは行配列を全保持せずFloatBufferへ直接格納。
- 録画時間の500ms更新は常に1本だけ予約し、音量メーター等のinvalidateから遅延更新が積み上がらないよう修正。
- AAC入力詰まり時にPCMを黙って捨てていた経路を廃止。出力をdrainして解消し、継続不能なら音声異常として明示。
- 外部マイク開始失敗時は自動マイクへ1回だけフォールバックし、失敗時だけ映像のみ録画へ移行。
- Muxer開始待ちバッファが上限を超えた場合、冒頭サンプルを黙って捨てず録画失敗扱い。
- OpenGLのクロップ率UI通知は最大約10Hzへ抑制。30/60HzでUIメッセージを積まないようにしました。
- OpenGLシェーダーのコンパイル/リンク失敗時に作成途中のGLオブジェクトを解放。

詳細は `CODE_HEALTH_AUDIT.md` を参照してください。

## 中心機能

- 45°水平維持
  - 補正角を±45°に制限してクロップを抑える普段使い向けモード
- 360°水平維持
  - 端末を大きく回しても水平を維持
  - 回転量によってクロップが大きくなるのは幾何学上避けられません
- 水平補正OFF
- 縦 9:16 / 横 16:9を撮影前に固定
- 水平追従: クイック / 標準 / なめらか
- クロップ上限: 1.10x / 1.30x / 水平優先 2.20x
- 現在のクロップ率表示
- 3分割グリッド / 水準器

## v1.4.0以降の水平センサー改善

水平角の取得は次の優先順位です。

1. GAME_ROTATION_VECTOR
2. ROTATION_VECTOR
3. GRAVITY
4. ACCELEROMETER

回転ベクトルを優先し、磁気の影響や単純な加速度ノイズを受けにくくしています。カメラをほぼ真上・真下へ向けたときは水平線そのものが定義しにくくなるため、最後の安定した角度を保持して急な回転を抑えます。

## フレームレート

- 30fps
- 60fps

端末のCamera2通常ストリームとH.264エンコーダの両方で利用できる組み合わせだけ表示します。

### 120fpsについて

v1.7.0でも120fpsは表示しません。

このアプリは `Camera2 -> SurfaceTexture -> OpenGL ES -> 水平補正/LUT -> MediaCodec` の経路を使います。Camera2の高速度撮影対応だけでは、水平補正済みの全120フレームを端末差なくMediaCodecへ渡せることを保証できないためです。専用の高速度処理経路を実装・検証するまで無効化しています。

60fps録画中はOpenGL処理側の実測FPSも監視し、継続して処理落ちした場合は解像度やLUTを下げるよう警告します。

- AE LOCK
  - 対応端末のみ操作可能
  - CaptureResultの実状態を確認

- ズーム（端末が公開する範囲のみ）
- ライト
- 前後カメラ切替

## 端末手ブレ補正

v1.3までの「弱 / 中 / 強」は廃止し、次の2状態だけに整理しました。

- OFF
- ON

対応端末ではAndroid 13以降の `PREVIEW_STABILIZATION` を優先し、なければ通常のVideo Stabilization、さらにそれもなければOISを使用します。

重要: 端末が設定要求を受け付けても、解像度・fps・出力Surfaceの組み合わせによって実際には手ブレ補正がOFFになる場合があります。そのためCaptureResultを監視し、設定画面では「ON（有効）」または「ON（端末確認中/無効）」として実状態が分かるようにしています。

v1.3までの「アクションモード」は、実態以上の効果を連想させるため削除しました。

- 音声ON / OFF
- 内蔵マイク
- USBマイク / USBヘッドセット

### 外部マイクの確認

`setPreferredDevice()`でマイクを指定した後、録音開始後に `AudioRecord.getRoutedDevice()` を確認します。Android側が別の入力へルーティングした場合は、実際に使われているマイク名を表示して警告します。

### v1.4.0以降で整理した音声機能

- イヤホンモニター
  - Java AudioRecord -> AudioTrack経路では端末差のある遅延が大きく、撮影用モニターとして品質を保証しにくいため削除
- 「マイクゲイン」という名称
  - 実際にはADC前段のアナログゲインではないため「デジタル音量補正」に変更
- 「風切り音低減」という名称
  - 実際の処理は低域ハイパス処理なので「低域カット」に変更

## 初回起動時の権限

初回ガイドの後に必要な実行時権限をまとめて要求します。

- CAMERA: プレビュー / 動画撮影
- RECORD_AUDIO: 動画音声
- BLUETOOTH_CONNECT: Android 12以降でBluetoothマイクを扱う端末

ストレージ全体アクセス権限は要求しません。Android 10以降はMediaStore経由で、このアプリ自身が作成する動画を `Movies/水平維持カメラ` に保存します。外部LUTはStorage Access Frameworkのファイル選択画面から読み込みます。

`MODIFY_AUDIO_SETTINGS` はイヤホンモニター削除に伴い不要となったためManifestから削除しています。

## 小型スマホ向けUI

v1.3で追加したコンパクトUIを維持しています。

- 360dp幅以下を小型画面として自動判定
- 小型画面では撮影方向ボタンを上段から隠し、設定内へ集約
- 縦小型: 上48dp / 情報18dp / 下64dp / 録画52dp
- 横小型: 情報バーを非表示、上48dp / 下58dp / 録画48dp
- 表示は小さくしても主要操作のタップ高さは確保
- 録画時間・残り時間・温度・クロップ率は操作バーを避けて配置

## v1.5.0 コード健康診断・修正

v1.5.0では機能追加を止め、Camera2 / OpenGL / MediaCodec / MediaMuxer / AudioRecord / UI / ライフサイクルを横断して監査しました。主な修正点です。

- 録画停止と `GLSurfaceView.onPause()` の競合を修正
  - 音声・映像エンコーダの終了を待ってからMP4を確定
  - 映像EOSを確認できない場合は壊れた可能性のある動画を正常保存扱いにしない
- MediaMuxer開始前の先頭サンプル消失を修正
  - 音声/映像2トラックが揃うまで短時間バッファし、開始後に書き戻す
- Camera2セッションの不要な再生成を削減
  - ズーム、露出、WB、ライト、手ブレ補正などは基本的にRepeatingRequest更新で反映
  - 解像度などSurface構成が変わる場合だけセッションを再生成
- 古いCamera2非同期コールバックが新しいカメラ状態を上書きする競合を世代番号で防止
- 録画中に変更してはいけない設定をUIロックOFF時でも固定
  - 解像度 / FPS / コーデック / 音声入力 / 前後カメラ / 撮影方向など
- センサー更新だけで同じカメラフレームを重複エンコードする可能性を修正
  - 新しいCameraフレーム到着時だけ録画エンコードと実測FPS計測を行う
- 前面カメラの左右反転に合わせて水平補正方向を補正
- H.264/HEVC対応判定をSurface入力対応エンコーダに限定
- 実際に対応判定した形式を処理できるMediaCodecを名前で選択して起動
- 音声エンコーダ停止中にMediaCodecを先に解放する競合を解消
- AAC入力バッファよりPCMブロックが大きい場合も分割投入してBufferOverflowを防止
- USB等の外部マイクが48kHz非対応の場合、公開サンプルレートから48kHz/44.1kHz/有効値を選択
- OpenGLの毎フレーム一時配列生成とUniform検索を廃止し、行列・Viewport・Uniform locationを再利用
- センサー更新ごとの不要なGL再描画を廃止し、カメラフレーム駆動へ整理
- GLコンテキスト再生成時に現在のLUTを再アップロード
- 録画中UIロック設定を切り替えた瞬間にも操作可否を即時反映
- Android 12以降のBluetooth権限判定で、Bluetooth非搭載端末を誤警告しないよう修正

詳細は `CODE_HEALTH_AUDIT.md` を参照してください。

## ビルド

必要環境:

- Android Studio / Android SDK 35
- Java 17
- Gradle 8.9相当

このソースには `.github/workflows/android.yml` があり、GitHub ActionsからDebug APKを作成できます。

この実行環境にはAndroid SDK / Gradle本体がないため、ここではAPK実ビルドは行っていません。Javaソースについては構文レベルの静的チェックを行い、Android SDKクラスが存在しないことによるエラー以外の明らかなJava構文エラーがないことを確認しています。
